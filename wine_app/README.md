# Сервис рекомендаций вин

Это учебное приложение на `Streamlit`, которое оценивает вероятность того, что вино хорошее. Для прогноза я использовала логистическую регрессию. Перед ней признаки масштабируются с помощью `StandardScaler`, поэтому в `model.joblib` сохранена не только сама модель, а весь pipeline.

Для приложения я выбрала порог `0.2689`. При таком пороге модель находит больше хороших вин, хотя среди рекомендаций иногда попадаются и посредственные, порог можно менять в боковой панели и смотреть, как из-за этого меняются решения модели и метрики

## Что есть в приложении

На вкладке `Одно вино` можно задать характеристики вина и посмотреть вероятность хорошего качества. Значения выбираются ползунками или вводятся вручную, оба варианта связаны между собой, поэтому при изменении одного поля обновляется второе

Минимальные и максимальные значения признаков взяты из `test.csv`, а начальные значения равны медианам. У признаков разная точность, поэтому шаг тоже отличается(иначе не оч удобно вводить значение, приходится угадывать, чтобы попасть в мин шаг). Например, для `density` используется пять знаков после запятой, а для `alcohol` один

На вкладке `Модельные метрики` выводятся матрица ошибок, `Precision`, `Recall` и `F1`. Там же находятся ROC и PR-кривые. Сами кривые строятся по вероятностям модели, а красные точки показывают результат для текущего порога

На вкладке `Прогноз по файлу` можно загрузить CSV сразу с несколькими винами. Приложение добавит вероятность хорошего качества и итоговое решение, после чего таблицу можно скачать. Если в файле не хватает нужных столбцов, вместо падения появится сообщение об ошибке

CSV для прогноза должен содержать следующие признаки:

```text
fixed_acidity
volatile_acidity
citric_acid
residual_sugar
chlorides
free_sulfur_dioxide
total_sulfur_dioxide
density
pH
sulphates
alcohol
is_red
```

На вкладке `Коэффициенты модели` можно посмотреть, какие признаки сильнее голосуют за хорошее вино, а какие против. Коэффициенты относятся к признакам после масштабирования. Этот график не меняется вместе с порогом, потому что модель уже обучена, а порог влияет только на итоговое решение

## Файлы проекта

- `app.py` содержит код приложения
- `model.joblib` содержит обученный pipeline
- `config.json` содержит выбранный порог
- `test.csv` содержит тестовую выборку
- `requirements.txt` содержит версии библиотек

Модель внутри приложения не обучается заново. Streamlit только загружает готовый файл и использует его для предсказаний

## Как запустить приложение

Проект рассчитан на Python 3.12.

Откройте PowerShell и перейдите в папку проекта:

```powershell
cd wine_app
```

Установите зависимости:

```powershell
pip install -r requirements.txt
```

После этого запустите приложение:

```powershell
streamlit run app.py
```

Streamlit выведет локальный адрес, по которому приложение откроется в браузере

## Кэширование

Streamlit заново выполняет весь `app.py` после каждого действия пользователя. Например, если передвинуть порог, скрипт снова пройдет все строки сверху вниз, поэтому модель и данные лучше не загружать заново без необходимости

Для модели я использовала `st.cache_resource`. Этот декоратор сохраняет один общий объект и при следующих запусках возвращает именно его, а не создает копию, для модели это подходит, потому что она уже обучена и внутри приложения не изменяется. Метод `predict_proba` только получает прогноз и не переобучает модель

Для `test.csv` и вероятностей на тестовой выборке используется `st.cache_data`. Этот декоратор предназначен для таблиц и результатов вычислений, он запоминает результат функции по ее аргументам и возвращает копию данных, поэтому один запуск приложения не сможет случайно изменить таблицу для остальных пользователей

Вероятности на тестовой выборке не зависят от порога, они считаются один раз, а при движении слайдера меняется только сравнение `probabilities >= threshold`-> поэтому повторно вызывать `predict_proba` для всей тестовой выборки не нужно

Если вызвать `joblib.load` без `st.cache_resource`, после каждого движения ползунка модель будет снова читаться с диска и собираться из файла `model.joblib`, итоговые прогнозы от этого не изменятся, но приложение будет делать лишнюю работу и медленнее отвечать
